# Импорт художественных ассетов (пилот C)

Этот пилот добавляет реальные модели и PBR-карты без замены старых объектов. В сохранении остаётся исходный игровой `type` (`box`, `barrel`, `fence`, `wall`, `floor`), а выбранная графика записывается в `properties.visual_asset`. Поэтому прежние коллизии, содержимое ящиков, перемещение и взаимодействия не требуют миграции. Неизвестный или отсутствующий вариант возвращается к обычному объекту. Тестовый GLB ящика и процедурные модели сохранены.

## Что включено

Все перечисленные файлы скачаны выборочно в 1K через официальный API Poly Haven с проверкой размера и MD5. [Лицензия Poly Haven: CC0](https://polyhaven.com/license). Исходные glTF, `.bin` и JPG лежат в `assets/sources/polyhaven/`; готовые GLB лежат отдельно в `app/static/models/art/`, PBR-карты в `app/static/materials/art/`. В каждом готовом наборе есть JSON с источником и контрольной суммой.

| Каталог | Источник | Особенность |
| --- | --- | --- |
| `art_rusty_barrel` | [Barrel_01](https://polyhaven.com/a/Barrel_01) | Ржавый нефтяной барабан, ~676 КиБ, 2682 треугольника. |
| `art_wooden_crate` | [Wooden Crate 02](https://polyhaven.com/a/wooden_crate_02) | ~2182 КиБ, 5176 треугольников. **Только тестовый образец:** стилистически ближе к сундуку, не утверждён для итогового набора. |
| `art_chainlink_fence` | [Modular Chainlink Fence](https://polyhaven.com/a/modular_chainlink_fence) | Сетка, две узкие вертикальные планки и две штатные стойки. Трубы, крепления и натяжные проволоки удалены по связным компонентам при импорте. PNG-альфа и `BLEND`/`DoubleSide` сохраняют тонкую сетку при уменьшении; только сетка не отбрасывает тень. Продольная ось X, `orientation: 0`. |
| `art_rusty_metal` | [Rusty Metal Sheet](https://polyhaven.com/a/rusty_metal_sheet) | Серо-голубая окрашенная сталь с рыжей коррозией и матовым покрытием. Отвергнутый `metal_plate_02` исключён из каталога; его исходники остаются в кешe. ID ассета сохранён для существующих локаций. |
| `art_aged_wood` | [Wood Planks Dirt](https://polyhaven.com/a/wood_planks_dirt) | Напольная PBR-поверхность. |
| `art_worn_plaster` | [Concrete Wall 003](https://polyhaven.com/a/concrete_wall_003) | Выцветшая окрашенная штукатурка, трещины и загрязнения вместо каменной кладки. |
| `art_dirty_earth` | [Dirt](https://polyhaven.com/a/dirt) | Напольная PBR-поверхность. |

Для каждого материала есть `color` (sRGB), `normal` (OpenGL) и `arm` (R=AO, G=roughness, B=metalness). Карты 1K JPG; отдельные ZIP-коллекции и 8K не загружались. У Poly Haven есть также ambientCG как возможный следующий CC0-источник, но в этой поставке смешивать источники не потребовалось.

Для импортированных PBR-полов верхняя и нижняя UV-проекция привязана к мировым X/Z с шагом 2 м. Это сохраняет фазу текстуры между соседними плитами даже при неполной плитке; процедурные материалы и боковые грани не меняются. Сам исходный рисунок досок при повторе 3×3 остаётся заметным и требует художественной оценки, но это не геометрическая рябь.

## Проверка в приложении

1. Запустите приложение обычным способом и откройте `/static/asset-preview.html`. Нельзя использовать `file://`, потому что JS-модули в браузере будут заблокированы.
2. Выберите модель и число экземпляров (1, 16 или 64). Для PBR-материала отображается одна непрерывная поверхность 6×6 м с повтором 3×3, без копланарного перекрытия образцов. Галочка диагностики показывает границы, оси и сетку 1 м. Поверните камеру и сравните границы повтора с геометрическими границами. Страница также показывает время создания/кадра, draw calls и счётчики `renderer.info.memory`.
3. В редакторе подлокации откройте каталог, группы «Художественные ассеты» и «PBR-материалы». Поставьте объект, выделите, поверните, сохраните и перезагрузите локацию. Старые варианты остаются рядом.
4. Для сравнения откройте `/static/performance-benchmark.html` и последовательно измерьте `Ассеты: procedural`, `Ассеты: тестовый GLB`, `Ассеты: художественные GLB` при одинаковом разрешении и числе кадров. Каждый режим содержит 24 объекта; модели подгружаются только при выборе режима. В консоли браузера строки `Graphics benchmark` включают FPS, p95, draw calls, треугольники, количество материалов, GPU-текстур/геометрий, первое время загрузки и ошибки.

Генератор [визуального полигона](../scripts/seed_visual_test_location.py) теперь включает семь пробных вариантов. Уже существующую локацию он **не меняет** до явного пересоздания: не запускайте `--rebuild`, если хотите сохранить ручные правки полигона. Для проверки без пересоздания просто разместите новые ассеты из каталога.

## Повторный импорт и добавление своего файла

Из `scripts/asset_import/`:

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run import -- --offline
```

`--offline` использует сохранённые исходники и API-манифесты. Без него CLI уточняет файлы у Poly Haven и докачивает только изменённое. `--force` повторно собирает выходные файлы. Скрипт останавливает импорт конкретного ассета при неверной контрольной сумме, отсутствующем JPG/PNG, пустой геометрии, отсутствующем материале или обязательном неподдерживаемом расширении. Ошибки выводятся с `assetId`; каталог не перезаписывается при частичной ошибке.

Для собственного GLB положите файл, например, в `assets/sources/local/` и выполните:

```powershell
npm.cmd run import -- --add assets/sources/local/my_crate.glb --id my_crate --base-type box --label "Мой ящик" --offline
```

Для `.gltf` положите связанные `.bin` и JPG/PNG рядом с исходником, сохранив относительные пути. Система проверяет их наличие. `--base-type` для новых моделей пока принимает `box`, `barrel` или `fence`: это сохраняет существующий игровой след и действия. Перед публикацией собственного файла самостоятельно подтвердите права на него; CLI не выдаёт пользовательский файл за CC0. При необходимости добавьте `--license "..."`.

Если модель слишком крупная или повёрнута не той стороной, не нужен Blender:

```powershell
npm.cmd run import -- --set my_crate --width 0.8 --depth 0.8 --height 0.7 --orientation-deg 90 --offline
```

Для отдельных экземпляров размеры и поворот можно менять штатными инструментами редактора. По умолчанию опора модели ставится в `bottom-center`; `--pivot center` и `--ground-clearance 0.008` доступны для исправления посадки. Новые параметры каталог получает автоматически из `assets.json` после успешного импорта, вручную редактировать JS не нужно. Добавление локального PBR-набора: `--add-material id --base-type wall --color color.jpg --normal normal.jpg --arm arm.jpg` (или `floor`).

## Совместимость и ограничения

Используется существующий Three.js 0.128.0 и существующий `GLTFLoader`. Готовые GLB содержат встроенные JPEG/PNG и геометрию; Draco, Meshopt, KTX2 и WebP **не требуются**. Для ржавой сетки остаётся поддерживаемое загрузчиком `KHR_texture_transform`. Оптимизация намеренно умеренная: удаление неиспользуемых узлов/ресурсов, дедупликация, необязательное уменьшение текстур по `maxTextureSize`; геометрия вслепую не упрощается. [glTF Transform](https://gltf-transform.dev/cli) используется только локально при сборке, в браузер новый пакет не добавлен. Дополнительное сжатие стоит оценивать позднее, когда будут реальные измерения на слабой видеокарте: декодеры увеличат сложность и могут ухудшить время первого показа.

Первый набор файлов независимый glTF-валидатор проверил без ошибок; он предупредил об отсутствии записанных tangent-атрибутов. После визуального отбора автоматические тесты проверяют структуру GLB, сетку с альфой, отсутствие горизонтальных металлических компонентов панели, две стойки, хеши и происхождение карт. Забор и новый металл дополнительно проверены в headless Chrome через локальную подачу тех же модулей Three.js 0.128.0: модели загрузились, сделаны кадры с двух сторон, ошибок выполнения и консоли не обнаружено. Это проверка предпросмотра; окончательное художественное принятие и FPS на реальной карте остаются за пользователем. Все карты принятых дерева, земли и штукатурки побайтно совпадают с прежними исходниками.

Размер одного технического GLB ящика: 11.7 КиБ, 192 треугольника, 2 материала без текстур. Тестовый художественный ящик: 2182 КиБ, 5176 треугольников, 1 материал и встроенные PBR-карты. Забор после очистки геометрии: 4268 КиБ; стоимость прозрачной сетки следует проверить при 16 и 64 экземплярах на слабой видеокарте. Повторные экземпляры используют общий кеш исходной геометрии и текстур, но отдельные изменяемые материалы; draw calls всё ещё могут расти. `renderer.info.memory` сообщает количество ресурсов, **не байты видеопамяти**. Не переносите синтетический FPS напрямую на настоящую локацию.
